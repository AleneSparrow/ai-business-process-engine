Widget Design

The client chat widget, in the Flywheel default theme.

Same visual system as the brand book — graphite, bronze, warm white — applied to web/widget/widget.js, the real embeddable widget. This is the out-of-box look before a business sets its own --aibp-color — and the direct design response to the Aug 17 UX audit.

UX Audit → Design Response

What this design fixes, and what it can't.

Mapped one-to-one against the seven live findings from the Aug 17 widget audit. A visual design can settle look, hierarchy, and interaction shape — it can't verify real-device rendering, which stays open.

✓

No "typing" indicator

Animated three-dot bubble, styled in bronze, replaces the plain "Sending…" text — shown inline in the thread where the reply will land.

✓

Launcher is a bare "Chat" button

Launcher is now the five-spoke wheel mark on a graphite disc, with a small amber "AI" dot — legible as Flywheel at a glance, not a generic chat icon.

✓

Business name & AI disclosure hidden until opened

A peek label ("Ask [Firm Name]") appears beside the closed launcher after a short delay, and the disclosure pill is pinned in the header, visible for the whole session — not just a scrollaway greeting line.

✓

Messages not distinguished by type

Assistant replies carry a small wheel avatar; human-staff replies carry an amber "team member" avatar and border; customer messages are solid bronze, right-aligned. Each row gets a timestamp.

✓

No dark theme

A full dark variant (.aibp-panel.dark) ships alongside light — same tokens as the brand book's product/dark-mode guidance, for businesses on dark-themed sites.

✓

Rest of dialogue is bare text

Service quick-replies and slot-picker buttons now share one pill style with the rest of the system — bronze outline, filled on hover — instead of looking like an unstyled afterthought.

–

Mobile CSS unverified on a real phone

This design carries mobile breakpoints forward (see Engineering Handoff), but confirming real-device rendering is a QA step, not something a visual design can settle on its own.

Design Tokens

Default values for widget.css.

The existing --aibp-color customization point stays exactly as-is — a business can still override it to match their own site. These are the recommended out-of-box values, before any business touches the setting.

TokenValueUsed for
--aibp-color#B87333Customer bubble, buttons, launcher accent — same as brand Bronze, business-overridable
--aibp-header-bg#151515Header and launcher background — brand Graphite
--aibp-panel-bg#FFFFFFPanel background, light theme
--aibp-history-bg#EEE8DCMessage thread background — brand Paper-2
--aibp-accent#D97B29AI-indicator dot on launcher, active states — brand Amber
--aibp-human#D97B29Human-handoff border/avatar — same Amber, reused to signal "a person is here now"
font-family (display)Century Gothic, FuturaHeader title only
font-family (body)system-ui stackEverything else — legibility over branding inside the thread
Dark theme is a single modifier class (.aibp-panel.dark) that swaps panel/history backgrounds to Graphite tones and lightens bubble borders — no separate component, no duplicated markup. Toggle it from the business's site-theme detection, or default to it when a business's own --aibp-color reads as a dark palette.
Engineering Handoff

What changes in the real widget.

1

widget.css

Replace the color/shape rules with the tokens above. Class names (.aibp-chat__*) stay identical — this is a re-skin, not a markup change, so widget.js needs no edits for styling alone.

2

Launcher markup

Swap the text-only launcher for the inline wheel SVG + .ai-dot span, and add the peek label element (shown once per session after ~2s, dismissable on first open) — small addition to widget.js.

3

Message rows

appendMessage(role, text) needs a role→avatar map and a timestamp element per row — role and timestamp are already available on each message object from the API.

4

Dark-mode trigger

Needs a decision: business-set flag in Business DNA, or prefers-color-scheme detection. Not resolved by this design — flagging for the technical workspace.
